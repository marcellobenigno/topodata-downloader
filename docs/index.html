O relevo do Brasil do TOPODATA, por área, direto no QGIS

Desenhe um retângulo no mapa. O plugin encontra as folhas TOPODATA que o intersectam, mostra quantos arquivos e quantos megabytes serão baixados e traz os GeoTIFF originais do INPE — altitude, declividade, curvaturas, orientação, forma de terreno, relevo sombreado e divisores — sem travar o QGIS.

⬇ Instalar o plugin ★ Código no GitHub

Visão geral

O que o plugin faz

O TOPODATA é o banco de dados geomorfométricos do INPE, derivado do SRTM e refinado para 1 segundo de arco (~30 m), com cobertura de todo o território brasileiro em folhas de 1° × 1,5°. Encontrar as folhas certas e baixar produto por produto é trabalhoso; o plugin faz isso a partir de uma área desenhada no mapa.

▭

Desenhe a área

Clique e arraste no mapa, em qualquer SRC. A seleção é convertida para EPSG:4326 e cruzada com a grade local de 556 folhas.

🧮

Saiba antes

Arquivos por produto e por folha, sem duplicatas, e o tamanho exato informado pelo servidor do INPE — ou “não disponível”, nunca um chute.

🛡️

Baixe com segurança

Em segundo plano, cancelável, com repetição limitada e retomada validada. Um arquivo incompleto nunca recebe o nome final.

🗂️

Use na hora

Cada GeoTIFF vira uma camada separada no grupo TOPODATA, com cores por classe nos produtos classificados.

O que ele não faz

  • não cria mosaicos, não recorta pela área desenhada e não reprojeta: os arquivos são os originais do INPE, folha inteira, com o nome original (ex.: 07S36_ZN.tif);
  • não calcula novas variáveis: declividade, curvaturas etc. são os produtos já publicados pelo INPE;
  • não funciona sem internet: a grade é local, mas os arquivos vêm do servidor do INPE.

Instalação

Instalar, ativar, verificar

Nenhuma biblioteca extra: o plugin usa só o PyQGIS e a biblioteca padrão do Python que vêm com o QGIS.

Requisitos e versões testadas

  • Mínimo declarado: QGIS 3.28. Testado no QGIS 3.44 (macOS), com testes automáticos num QGIS sem tela. QGIS 4 (Qt6) e Windows ainda não foram testados.
  • Internet para consultar tamanhos e baixar os arquivos (servidor data.inpe.br).
  • Espaço em disco: de 0,4 MB a ~120 MB por arquivo, conforme o produto (veja Produtos).

  1. Gere o ZIP do plugin

    Baixe o código do repositório (Code → Download ZIP ou git clone) e, na pasta dele, rode o script abaixo. Ele cria dist/topodata_downloader-0.1.0.zip.

    git clone https://github.com/marcellobenigno/topodata-downloader.git
cd topodata-downloader
python scripts/make_zip.py

  2. Instale pelo QGIS

    Complementos → Gerenciar e instalar complementos → Instalar a partir do ZIP, escolha o arquivo e confirme. Como o plugin é experimental, marque Mostrar também os complementos experimentais nas Configurações do gerenciador.

  3. Verifique

    Na aba Instalados, TOPODATA Downloader deve estar marcado. O botão aparece na barra de complementos e em Raster → TOPODATA Downloader.

Instalação para desenvolvimento (link simbólico)

Ligue a pasta topodata_downloader/ do repositório à pasta de complementos do seu perfil; cada mudança no código vale depois de recarregar o plugin (Plugin Reloader) ou reiniciar o QGIS.

# macOS
ln -s "$PWD/topodata_downloader" \
  "$HOME/Library/Application Support/QGIS/QGIS3/profiles/default/python/plugins/topodata_downloader"
# Linux
ln -s "$PWD/topodata_downloader" \
  "$HOME/.local/share/QGIS/QGIS3/profiles/default/python/plugins/topodata_downloader"

No Windows, a pasta é %APPDATA%\QGIS\QGIS3\profiles\default\python\plugins; copie a pasta para lá ou crie uma junção com mklink /J.

Proxy. O plugin usa o proxy HTTP definido em Configurações → Opções → Rede. Um proxy ligado mas inacessível faz a consulta de tamanhos mostrar “não disponível” e os downloads falharem com “Não foi possível conectar ao servidor do INPE”. Sem proxy configurado, vale o proxy do sistema.

Primeiros passos

Do retângulo às camadas no mapa

Um primeiro uso na Paraíba, entre João Pessoa e Campina Grande, com produtos pequenos (alguns MB por folha) para terminar em poucos segundos.

  1. Ative a ferramenta e desenhe

    Clique no botão Baixar dados TOPODATA por área e clique e arraste no mapa sobre a região de interesse. Esc cancela; um clique sem arrasto é recusado com um aviso. Resultado esperado: o diálogo abre com oeste, sul, leste e norte em graus e as folhas encontradas.

  2. Escolha a pasta e os produtos

    Escolha a pasta de destino (ela é criada se não existir) e marque, por exemplo, Decliv. (A), Orientação — octantes e Forma de terreno. Resultado esperado: o resumo mostra os arquivos por produto e, depois de alguns segundos, o tamanho exato de cada um.

  3. Baixe

    Baixar N arquivo(s) passa para a página de execução. O QGIS continua livre para uso; a tarefa também aparece na barra de status. Resultado esperado: “Concluído com sucesso” e as camadas no grupo TOPODATA.

💡 Refazer seleção no mapa volta ao mapa sem perder a pasta, os produtos e as opções. O diálogo também lembra a última pasta e os produtos marcados entre sessões.

* Faixa medida por consulta HEAD em quatro folhas de tamanhos diferentes (01N495, 09S375, 23S465, 33S54_). O plugin mostra o tamanho exato de cada arquivo da sua seleção antes de baixar.

Por que o plugin aplica cores às classes? Os GeoTIFF classificados do INPE trazem uma tabela de cores em tons de cinza quase pretos (valor v → cinza v−1); abertos direto no QGIS, parecem pretos. Ao carregar, o plugin define um estilo de camada com uma cor por classe. É só o estilo: o arquivo não é alterado, e você pode trocar as cores nas propriedades da camada. A ordem das classes segue a descrição do INPE; confira a legenda oficial antes de interpretar cada classe.

Como funciona

Regras que definem o que é baixado

Três escolhas explicam o comportamento do plugin: quais folhas entram, como a contagem e o tamanho são calculados e como um download é considerado completo.

Quais folhas entram: intersects

A grade (grade_topodata.geojson, 556 polígonos em EPSG:4326, campos scene e url) vai junto com o plugin e é indexada uma vez por sessão. Um índice espacial pré-seleciona as folhas pela caixa envolvente; cada candidata é confirmada com intersects sobre a geometria real. Folhas apenas tocadas pela borda ou por um vértice do retângulo entram.

  • A cruza a divisa entre 06S375 e 06S36_: entram as duas.
  • B está dentro de 07S36_, com a borda oeste exatamente na divisa: 07S375, só tocada, também entra.
  • C está inteiro em 07S375: só ela entra.

As folhas reais têm meia margem de pixel (~0,000139°, ~15 m) além do limite nominal, então vizinhas se sobrepõem levemente. Um retângulo que começa até 15 m antes da divisa já inclui as duas folhas.

Seleção em outros sistemas de referência

A seleção é feita no SRC do projeto (UTM, Web Mercator, Policônica…). O retângulo vira um polígono com 32 vértices extras por lado e é transformado para EPSG:4326 com o contexto de transformação do projeto. Num SRC projetado a consulta usa a forma real da seleção em coordenadas geográficas, não uma caixa envolvente maior. O diálogo mostra a caixa envolvente da seleção já em graus.

Contagem e tamanho

Arquivos
Produtos marcados × folhas encontradas, uma URL por par; URLs repetidas contam uma vez. O resumo mostra os arquivos por produto, por folha e o total. Uma folha cuja URL fuja do padrão é ignorada e informada — nada é adivinhado.
Tamanho
Não há índice local de tamanhos e o servidor não lista diretórios. O plugin pergunta ao servidor, em segundo plano, o Content-Length de cada arquivo (requisição HEAD, sem baixar dados; 6 em paralelo, guardadas na sessão). É o tamanho exato do arquivo atual.
Sem resposta
O total aparece como “não disponível”, com “pelo menos X” para a parte conhecida. O download pode ser feito mesmo assim.
Aviso de volume
A partir de 40 arquivos ou 5 GB o resumo avisa e o download pede confirmação — nada é bloqueado.

Download seguro

  • Nome final só para arquivo completo. Os bytes vão para .part; o nome final só é dado depois de conferir o tamanho contra o Content-Length e o cabeçalho TIFF (uma página de erro, por exemplo, é descartada).
  • Retomada validada. O ETag do servidor fica em .part.json. Na retomada são enviados Range e If-Range; os bytes só são anexados se a resposta for 206 com Content-Range começando exatamente no fim do parcial e com o mesmo total. Arquivo mudado no servidor, parcial sem ETag ou faixa que não confere: o parcial é descartado e o download recomeça do zero.
  • Repetições limitadas. Falhas temporárias (conexão, tempo esgotado, HTTP 408/425/429/5xx) têm até 4 tentativas, com esperas de 2, 5 e 10 s. Erros definitivos (404, 403) não são repetidos.
  • Arquivos que já existem são reutilizados se o tamanho for igual ao do servidor e o cabeçalho TIFF for válido. Se forem diferentes, ou com Baixar novamente marcado, são baixados de novo, e o arquivo antigo só é substituído quando o novo estiver completo.
  • Cancelamento a qualquer momento: verificado a cada bloco de 256 kB e durante as esperas. O arquivo em andamento fica como .part; os não iniciados aparecem como “Cancelado”.

Carregamento no QGIS

Com Carregar as imagens no QGIS ao concluir marcado, cada arquivo disponível (baixado ou reutilizado) vira uma camada separada no grupo TOPODATA, com o caminho final e o nome 07S36_SA — Decliv. (A). Arquivos que já estão no projeto não são duplicados; os que o GDAL não abre aparecem na tabela com o motivo.

Ajuda

Problemas comuns

Cada mensagem do plugin traz uma explicação curta; o detalhe técnico fica em Detalhes técnicos (pode ser copiado) e em Exibir → Painéis → Mensagens de log, aba TOPODATA Downloader.

O tamanho aparece como “não disponível”

A consulta HEAD ao servidor do INPE falhou para algum arquivo: sem internet, proxy do QGIS inacessível ou servidor fora do ar. Confira a conexão e o proxy em Configurações → Opções → Rede e use Consultar tamanhos novamente. O download pode ser feito mesmo sem o tamanho; o progresso passa a ser contado por arquivos.

“Não foi possível conectar ao servidor do INPE”

A rede não alcança data.inpe.br. A causa mais comum é um proxy ligado no QGIS que não existe mais; desligue-o ou corrija-o em Configurações → Opções → Rede. As falhas temporárias já são repetidas automaticamente até 4 vezes.

Ficaram arquivos .part e .part.json na pasta

São downloads interrompidos (cancelamento, falha ou QGIS fechado). Baixe de novo com a mesma pasta: o plugin retoma do ponto em que parou se o servidor confirmar que o arquivo não mudou; senão recomeça. Pode apagá-los com segurança se não for continuar.

Um arquivo aparece como “Já existia (verificado)”

O arquivo já estava na pasta com o mesmo tamanho do servidor e cabeçalho TIFF válido, então não foi baixado de novo. Para forçar, marque Baixar novamente arquivos que já existem na pasta.

As imagens classificadas aparecem pretas

Acontece ao abrir os arquivos classificados direto no QGIS (sem o plugin): a tabela de cores que vem nos arquivos é cinza quase preta. Carregue-os pelo plugin (Carregar no QGIS) para receber as cores por classe, ou escolha Valores únicos em Propriedades → Simbologia.

Quanto tempo leva?

Depende da conexão, do servidor do INPE e do volume. Produtos classificados têm poucos MB por folha; os numéricos e o relevo sombreado têm 30–120 MB por folha cada um. Marcar todos os produtos numa área de 4 folhas passa de 1 GB.

Fechei o diálogo durante o download

O plugin pergunta antes (inclusive com Esc). Ao confirmar, o download é cancelado: os arquivos concluídos ficam, o em andamento vira .part.

Dados

Sobre o TOPODATA

Banco de dados geomorfométricos do Brasil, do Instituto Nacional de Pesquisas Espaciais (INPE). Os dados de elevação do SRTM (fevereiro de 2000) foram refinados por krigagem de 3 para 1 segundo de arco, para favorecer as derivações geomorfométricas, e todo o processamento foi feito em coordenadas geográficas, sem reprojeção.

~30 m

pixel de 0,00027777° (1″), refinado do SRTM de 3″ (~90 m)

556

folhas de 1° × 1,5°, articulação 1:250.000, cobrindo todo o Brasil

4326

coordenadas geográficas WGS 84; altitudes ortométricas (EGM96)

COG

GeoTIFF otimizado para nuvem; Float32 numéricos, Byte classificados

Modelo de superfície, não de terreno. O SRTM (banda C) registra uma altura entre o topo da vegetação e o solo em áreas florestadas, e o topo das construções em áreas urbanas. A escala de trabalho compatível é 1:100.000.
  • Página oficial e termos de uso: data.inpe.br/dados/topodata.
  • Valeriano, M. M.; Rossetti, D. F. Topodata: Brazilian full coverage refinement of SRTM data. Applied Geography, 32(2), 300–309, 2012.

O plugin não é um produto do INPE; só automatiza o acesso aos arquivos públicos. Cite o TOPODATA/INPE ao usar os dados.
