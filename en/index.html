TOPODATA Downloader for QGIS

A QGIS plugin that identifies the TOPODATA grid tiles that intersect the selected area and downloads the corresponding products. Before downloading, it shows the number of files and, when the server reports it, a size estimate based on the HTTP header. Files are kept as they are — no mosaicking, clipping or reprojection.

⬇ Install the plugin ★ Source on GitHub

Overview

What the plugin does

TOPODATA is a nationwide geomorphometric database of Brazil developed by the National Institute for Space Research (INPE). Its products are derived from the elevation data of the SRTM mission (Shuttle Radar Topography Mission) and include topographic variables and classified products. The dataset was refined from the original 3 arc-second spacing to 1 arc-second by kriging, to support geomorphometric derivations. This refinement adds no independent elevation information and must not be read as an equivalent increase in the effective spatial resolution or in the accuracy of the source data. [1] [2]

Versions and project status. QGIS 3.28 or later (declared minimum); tested on QGIS 3.44 for macOS. Automated tests ran on a headless QGIS. Windows and QGIS 4 have not been tested yet. The plugin interface is in Brazilian Portuguese; on this page, interface labels are quoted in Portuguese with an English translation.

The plugin identifies the TOPODATA grid tiles — the map sheets of the cartographic index — that intersect the selected area and automates the download of the corresponding products. The TOPODATA grid is queried locally; size lookups and raster downloads need a connection to the INPE server.

What the plugin does not do

  • It does not mosaic the rasters or clip them to the selected area.
  • It does not reproject or modify the downloaded files. QGIS may reproject layers on the fly for display only, following the project CRS; this does not change the file on disk.
  • It does not recompute slope, curvature or other variables. These products are provided by TOPODATA/INPE.
  • It does not turn TOPODATA elevation values into a terrain model free of vegetation and buildings.
  • It does not work fully offline: the grid is local, but size lookups and file transfers need internet access.

Installation

Install, enable, verify

No extra Python libraries: the plugin uses PyQGIS and the Python standard library shipped with QGIS.

Requirements

  • QGIS 3.28 or later, the minimum version declared by the project.
  • Internet access to query the INPE server (data.inpe.br) and download the files.
  • Enough disk space for the chosen set. Sizes vary a lot by product and tile (see Products); use the plugin summary as a reference when the server reports the sizes.

QGIS 4 and Windows have not been tested yet. Do not read “declared minimum version” as a guarantee of compatibility on every platform: check the tests of the published plugin version.

Install from ZIP

  1. Build the package

    Download the source from the plugin repository (Code → Download ZIP) or clone it, then build the package from its folder. The script creates dist/topodata_downloader-<version>.zip, matching the project version.

    git clone https://github.com/marcellobenigno/topodata-downloader.git
cd topodata-downloader
python scripts/make_zip.py

  2. Install it in QGIS

    Plugins → Manage and Install Plugins → Install from ZIP, select the package and confirm. If the plugin is still flagged as experimental, tick Show also experimental plugins in the manager settings.

  3. Verify

    In the Installed tab, check that TOPODATA Downloader is enabled. The command should appear on the Plugins toolbar and in Raster → TOPODATA Downloader.

Development install

Link the plugin folder into the plugins folder of your QGIS profile. After changing the code, reload the plugin with a tool such as Plugin Reloader, or restart QGIS.

# macOS
ln -s "$PWD/topodata_downloader" \
  "$HOME/Library/Application Support/QGIS/QGIS3/profiles/default/python/plugins/topodata_downloader"

# Linux
ln -s "$PWD/topodata_downloader" \
  "$HOME/.local/share/QGIS/QGIS3/profiles/default/python/plugins/topodata_downloader"

On Windows, the profile folder is usually %APPDATA%\QGIS\QGIS3\profiles\default\python\plugins. Copy the plugin folder there or create a junction with mklink /J.

Network proxy. The plugin uses the proxy configured in QGIS under Settings → Options → Network. A proxy that is enabled but unreachable can block both size lookups and downloads. If needed, check the proxy settings of QGIS or of the operating system.

Quick start

From a rectangle to layers on the map

The whole flow, from the selection on the map to the layers in the project. The grid and plan steps run offline; sizes and downloads query the INPE server.

  1. Draw the area

    Click Baixar dados TOPODATA por área (Download TOPODATA data by area). On the map, click and drag to draw a rectangle over your area of interest. Press Esc to cancel. A click without dragging does not define a valid area.

  2. Check the selection

    In the dialog, check the geographic extent and the tiles found.

  3. Choose the folder and products

    Choose the destination folder and tick one or more products. Check the number of files and the sizes reported by the server; the size lookup can take a few seconds.

  4. Download and load

    Start the download. It runs in the background so the QGIS interface stays responsive. When it finishes, the rasters are loaded into the project if the corresponding option is enabled.

Transfer time depends on the number and size of the files, the connection and the availability of the server. Ticking many products over several tiles can add up to a large download. The plugin summary shows the number of files and, when possible, the total size before you start.

Products

The 16 TOPODATA products

TOPODATA publishes 16 products per tile, identified by codes. Numeric data are distributed as 32-bit real values (Float32); classified products use 8-bit integers (Byte/UInt8), according to the general characteristics published by INPE. [1]

The names below describe the content of each product. To interpret class limits, sign conventions or special values, check the official legend and metadata of the product. The colours applied by the plugin are a QGIS symbology setting; they do not change pixel values. The plugin itself labels products in Portuguese (e.g. Decliv. (A)).

Before downloading, the plugin looks up the Content-Length reported by the server, when available; without a reliable answer, the size is shown as unavailable rather than as an inferred value.

Notes on units and interpretation

  • Numeric slope SN is given in percent, not degrees. The relation between percent and angle is not linear; 100% is a 45° slope.
  • Aspect is an azimuth associated with the direction of steepest descent of the slope. Do not confuse it with map orientation or the direction of map north.
  • Vertical and horizontal curvature describe different aspects of the surface shape. Vertical curvature characterises the shape in profile; horizontal curvature characterises convergence or divergence in plan. Interpret the sign according to the product convention, not by assumption from other software.
  • For curvatures, the official TOPODATA documentation gives an angular unit per metre. Do not convert or directly compare the values with curvatures computed by another algorithm without checking the mathematical definition, scale, units and derivation method. [1] [2]
  • Product codes are TOPODATA identifiers. The letters “A”, “B” and “C” distinguish classifications, not quality levels of the data.
  • Colours are display conventions. Check the classes and the official legend before any thematic interpretation.

Spatial query and downloads

How the spatial query and the download work

Which tiles are included, how files are counted and sized, how a download is validated and how files reach the project.

Intersection with the grid

The plugin ships a local grid (grade_topodata.geojson) with 556 polygons in EPSG:4326 and the fields scene and url. A spatial index picks candidates by extent; each candidate is then tested against the actual geometry of the rectangle with the topological predicate intersects.

With this rule, a tile is selected when its geometry shares any part with the rectangle, including an intersection only along an edge or at a vertex.

  • A crosses the boundary between 06S375 and 06S36_: both are included.
  • B lies inside 07S36_, with its west edge exactly on the boundary: 07S375, only touched, is included too.
  • C lies entirely in 07S375: only that tile is included.

Tile geometries may extend slightly beyond the nominal sheet limits; neighbouring tiles may therefore be selected near a boundary.

Selections in other reference systems

The selection is drawn in the project CRS and transformed to EPSG:4326 before the query. So that a projected rectangle is not treated as a plain box in geographic coordinates, its outline is densified (32 extra vertices per side) before the transformation. The dialog shows the geographic bounding box of the selected area.

File count and size

Files
Files are counted from the product–tile pairs and the URLs resolved from the grid. Repeated URLs count once. If a URL or identifier does not follow the recognised pattern, the plugin reports the item and does not try to guess its address.
Size
The plugin sends HTTP HEAD requests to the server, without transferring raster content. When the server returns Content-Length, that value is the size announced for the response. Several files are queried in parallel and results are cached for the session.
No answer
If some answers are missing, the plugin shows the known subtotal and marks the total as unavailable or as a known minimum.
Volume warning
From 40 files or 5 GB on, the summary shows a warning and asks for confirmation. These limits are usability warnings; they do not guarantee duration, availability or enough free disk space.

Integrity, retries and resume

  • Final name only after validation. Data are first written to partial .part files. The final name is applied only after the received size is compared with the announced size and the GeoTIFF header is checked. This reduces the risk of treating an error page or an incomplete transfer as a valid raster; it does not replace a full checksum validation, which the server does not provide.
  • Validated resume. To resume a partial file, the plugin keeps metadata in .part.json and uses the Range and If-Range headers. Bytes are appended only if the response signals range support (206 Partial Content) and Content-Range confirms the expected start offset and total size. Otherwise the partial file is discarded and the download restarts, with no unsafe appending.
  • Limited retries. Temporary failures — lost connection, timeout, or HTTP 408, 425, 429 and 5xx responses — get up to four attempts, with waits of 2, 5 and 10 seconds. Permanent errors such as 403 or 404 are not retried automatically.
  • Cancelling. Finished files are kept. The file in progress may remain as .part for a later attempt, if its metadata allow a safe resume. Files not yet started are marked as cancelled.
  • Running again. Existing files are reused if they pass the checks; you can choose to download them again.

Loading into QGIS

When Carregar as imagens no QGIS ao concluir (Load the images into QGIS when finished) is ticked, each available file is added as a separate raster layer in a group named TOPODATA. The layer name combines the file name and the product label, e.g. 07S36_SA — Decliv. (A).

Loading does not mosaic, clip or reproject the data. Layers that cannot be opened are reported with the reason, and files already loaded in the project are not added again. The symbology applied to classified layers is only a visual representation in the QGIS project: it does not change the values stored in the GeoTIFF and can be edited in the layer properties.

Data and limitations

TOPODATA data

TOPODATA is derived from SRTM mission data, acquired in February 2000 by C-band synthetic aperture radar interferometry (InSAR). [1]

Origin, reference system and pixel meaning

The dataset is distributed in geographic coordinates, with the WGS 84 horizontal datum (EPSG:4326), and orthometric heights referred to the EGM96 geoid model. The national coverage is organised in tiles of 1° latitude by 1.5° longitude, matching the 1:250,000 map sheet index. [1]

The 1 arc-second pixel corresponds to about 30 m at the Equator. Because the pixel is defined in angular coordinates, its east–west linear size decreases with latitude. Moreover, the refinement from 3 to 1 arc-second is a kriging interpolation aimed at supporting geomorphometric derivations; it is not equivalent to acquiring independent observations at an original 30 m spacing, nor does it demonstrate 30 m accuracy. [1] [2]

The recommended working scale for TOPODATA is 1:100,000. This must not be read as a guarantee of uniform positional accuracy, as a suitable scale for every application, or as an automatic consequence of the pixel spacing. Assess whether the product fits the scale, the relief, the land cover and the purpose of your analysis. [1]

SRTM limitations and interpretation as an elevation model

A surface model, not a terrain model. INPE characterises the SRTM source as a digital surface model (DSM), not a digital terrain model (DTM). C-band radar interacts with vegetation and built structures; the estimated elevation may reflect the phase centre of the signal within the vegetation volume, not necessarily the bare ground or the top of the canopy. The response varies with the structure and properties of the cover. In urban areas, buildings can also affect the values. [1]

The ZN layer should therefore be treated as an SRTM-derived elevation model, with the limitations of a radar observation and of TOPODATA processing. Do not describe it as a bare-earth DTM or assume the height matches the top of the canopy. For studies that depend on ground elevation under vegetation, consider a source designed for that purpose and validate the data against independent references.

Products and geomorphometric processing

TOPODATA derives variables such as slope, aspect, and vertical and horizontal curvature from the refined DEM. The processing was developed for this dataset and includes its own derivation and post-processing steps. Recomputing these variables in another GIS from the ZN raster may therefore give results that differ from the products published by INPE. [1] [2]

Shaded relief is a visualisation of simulated illumination and should not be used in place of an elevation model. Classified products condense ranges or combinations of variables into discrete codes; for quantitative interpretation, use the corresponding official legend and documentation.

Citing the data

The plugin is not an INPE product. It automates access to files made available by TOPODATA. When you use the data, cite TOPODATA/INPE and the relevant methodological reference:

Valeriano, M. M.; Rossetti, D. F. Topodata: Brazilian full coverage refinement of SRTM data. Applied Geography, v. 32, n. 2, p. 300–309, 2012. https://doi.org/10.1016/j.apgeog.2011.05.004

See also the official TOPODATA page at INPE (in Portuguese) for up-to-date information on data, products, access and symbology.

Troubleshooting

Common problems

Each plugin message has a short explanation; the technical detail is under Detalhes técnicos (Technical details) and in View → Panels → Log Messages, tab TOPODATA Downloader.

The size shows as “não disponível” (not available)

The HEAD request did not return a usable size for one or more files. Check internet access, the QGIS proxy and the server availability. Use Consultar tamanhos novamente (Look up sizes again) once the connection is back. The download can start even without knowing the total size in advance.

Could not connect to the INPE server

Make sure your network can reach data.inpe.br. Check whether a proxy is enabled in QGIS and whether its settings are still valid. Temporary failures are retried within the limits described in Integrity, retries and resume.

There are .part and .part.json files in the folder

These files mark an interrupted or incomplete transfer. Running again can resume the transfer if the metadata and the server response confirm continuity; otherwise the plugin restarts the file. You can delete partial files by hand if you do not intend to resume; do not delete final files that have already been validated.

A file shows as “Já existia (verificado)” (already existed, verified)

The destination file already existed and passed the plugin's validation criteria. To transfer it again, tick Baixar novamente arquivos que já existem na pasta (Download again files that already exist in the folder).

Classified products look dark or almost black

The appearance depends on the symbology attached to the raster and on how QGIS interprets the values. Use the plugin's load option to apply the intended style, or set the symbology in Layer Properties → Symbology. Symbology does not change the file values. Check the product legend before giving meaning to the colours.

How long does it take?

It depends on the number of files, the size of each product, the bandwidth and the server availability. The size ranges per product in the table are only a reference; rely on the values the plugin shows for the current selection.

I closed the dialog during the download

The plugin asks for confirmation; confirm the cancellation only if you want to stop the task. Finished files remain available; the transfer in progress may leave a partial file to be resumed later.
